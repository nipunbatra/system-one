Rule of thumb. If the answer comes from a list, a scale, a yes or no, or a place in the input, it is a System 1 call. If the answer has to be written, it needs an LLM.

PART 2How an LLM answers

  1. Tokens. Text becomes integers. Our email is 13 tokens from a vocabulary of 151,936.
  2. Vectors. Each id picks a row of a table: 896 numbers.
  3. Attention. Each token's vector becomes a weighted mix of the tokens before it.
  4. Blocks. Attention and a small network, repeated 24 times. Keep the vector at the last position.
  5. Logits. An output layer turns that vector into 151,936 scores, one per token.
  6. Softmax. Scores become probabilities.
  7. Loop. Pick a token, append it, run everything again.

Encoder or decoder. In an encoder a token sees both sides, and the output is a vector per token (BERT). In a decoder a token sees only its left, and the output is the next token (GPT, Claude, Qwen). Chat models are decoders, which is why they write one token at a time.

PART 3Read, don't write

THE IDEAThe answer is already in the first forward pass. Keep the logits of the option letters, apply softmax, and skip the writing.
optionlogitminus 23.98e to thatprobability

letter_ids = [tok.encode(c)[0] for c in "ABCDEFGH"]

def decide(state, question, options):
    x = tok(prompt(state, question, options), return_tensors="pt")
    logits = model(**x).logits[0, -1]            # one forward pass
    keep = logits[letter_ids[:len(options)]]     # only the options
    return keep.softmax(-1)                      # renormalise

Reading took 36 ms against 259 ms for writing: 7.2 times faster. Counting written answers instead needs 97 samples for ±0.10 (1.96² × 0.25 / 0.10² = 96.04).

Score. The probability-weighted level: 0 × 0.94 + 1 × 0.04 + 2 × 0.02 = 0.08.

Turning a chat model into a decision model

  1. Remove the vocabulary output layer.
  2. Let every token see both sides, since nothing is written.
  3. Attach a small head and train, with LoRA (small trainable additions to the frozen blocks).

The recipe of System One Gemma, as described by Roitman. Our notebook 2 does steps 1 and 3.

PART 4Calibration

THE DEFINITIONAmong all the answers given with probability p, a fraction p are correct. A forecaster who says 80% on ten days is calibrated if it rains on eight.

Confidence is the largest softmax probability, and the answer is the option that has it. Calibration is a property of a group of predictions, never of one.

ECE = Σbins (nbin / N) × | accuracy − confidence |
def ece(conf, correct, n_bins=10):
    edges = np.linspace(0, 1, n_bins + 1)
    total = 0.0
    for lo, hi in zip(edges[:-1], edges[1:]):
        in_bin = (conf > lo) & (conf <= hi)
        if in_bin.any():
            gap = abs(correct[in_bin].mean() - conf[in_bin].mean())
            total += in_bin.mean() * gap
    return total

  • T above 1 flattens the probabilities, T below 1 sharpens them. The order of the options never changes, so accuracy stays the same.
  • Choose T on held-out items, by the lowest log loss (the average of −log of the probability given to the correct option). Ours: T = 3.3, log loss 1.42 → 0.65.
  • Never choose T on the test items.

RLCD, "reinforcement learning for calibrated decisions", is TypeSafe's name for how Jev is trained. Only the goal is published.

Proper scoring rules

Ten customers send the same email, so the model gives all ten the same P(refund). Later, 7 wanted a refund and 3 did not. Which number should it have said?

Brier penalty = (p − y)²    log loss = −log pcorrect
saysBrier total: 7 × (p − 1)² + 3 × p²log loss totalright answers
0.57 × 0.25 + 3 × 0.25 = 2.506.937
0.77 × 0.09 + 3 × 0.49 = 2.106.117
0.97 × 0.01 + 3 × 0.81 = 2.507.657
0.997 × 0.0001 + 3 × 0.98 = 2.9413.897

Counting right answers cannot tell 0.7 from 0.99. Both penalties are lowest at the true rate, 0.7. A rule with this property is proper, and cross-entropy, the usual classification loss, is one.

Exam picture. With +4 for right and −1 for wrong you mark an answer only when you are more than 20% sure (4p − (1 − p) = 0). The marks shape the student, and the reward shapes the model.

A proper score is the right incentive, not a guarantee: a small model, noisy labels or new kinds of input can still leave a trained model miscalibrated.

PART 6Putting it to work

A recipe for your own problem

  1. Write the state and the questions. Give each question a type.
  2. Label a small test set yourself. One or two hundred real inputs.
  3. Try a general model with no training. Record accuracy and draw the reliability diagram.
  4. If the confidence is off, calibrate. Fit a temperature on half the labels, check on the other half.
  5. If the accuracy is short, train. Fine-tune on labelled rows, or train a head on frozen vectors.

A general decision model takes the question as input, so a new question needs new text and no new training. Training happens once, on many kinds of question.

A head that takes any question

Write the options one per line and read the model's vector at the end of each line. One small trained scorer turns each vector into a score, then softmax. It has one output, so it works for any number of options and any question.

Our experiment on the frozen Qwen2.5-0.5B, 57,473 trained numbers, tested on three kinds of question it never saw. Trained on 5 kinds: 0.51, 0.59, 0.48. Trained on 13 kinds: 0.72, 0.85, 0.63. Letters, untrained: 0.73, 0.80, 0.49. Variety of training questions is what makes it general.

Thresholds from costs

act when p > c / (c + b)

b is the benefit of a right automatic action and c the cost of a wrong one. A wanted refund saves ₹50, an unwanted one costs ₹450 to undo: 450 / (450 + 50) = 0.90. Our email reads 0.74, so a person looks at it. The rule holds only for calibrated probabilities.

Limits to keep in mind

  • It returns probabilities and no reasons.
  • Default thresholds can fail; tune them on your data.
  • Counting and arithmetic belong in code.
  • Calibration is measured on past data and drifts when inputs change. Reordering options can move the probabilities.
  • Rare events: most flagged items can still be false alarms.
